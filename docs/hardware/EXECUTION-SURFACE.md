using the other family's compiled cmdline. No complete watchdog/feeder or
reset-policy trace has yet been established in the kernel/daemons/driver.

## Updater verification and installation boundaries

This section describes **only the extracted older updater**. `U@offset` means a
file offset in `bin/upgrade`, SHA-256
`d17809f33003856d66f5406e080081ca8f0e3954a8d5536bb8f541010b8cce1a`;
its corresponding text VA is `0x10000000 + offset`. `C@offset` means the file
offset/link-time VA in `lib/libsonoscrypto.so.1`, SHA-256
`03653fc9205ff23ad583506684f93387c444ac2b726a01bfa1ff18b6d7594c6c`.
ELF mappings and byte-checked disassembly are preserved in [images.json](evidence/execution-20261028/images.json).
Nearest-symbol labels in stripped code are not recovered function names.

1. **Two distinct signature handlers.** The 16-byte handler table at
   `U@0x1a2c0–0x1a39f` maps record `0xffffffff` to VA `0x100074e4` and record
   `0x11` to VA `0x100075c8`. Dispatch calls the selected callback at
   `U@0x7b30–0x7b50`. See [table](evidence/execution-20261028/record-handlers.json)
   and [dispatch](evidence/execution-20261028/upgrade-record-dispatch.dis.txt).
2. **Legacy RSA/MD5.** [Legacy handler](evidence/execution-20261028/upgrade-legacy-signature.dis.txt)
   `U@0x7580–0x75ac` finalizes a digest, passes scheme 1, hash selector 2,
   length 16 and the signature to `ZZ0109`, and requires result 1. Selector 2
   maps to MD5 in [hash wrappers](evidence/execution-20261028/crypto-hash.dis.txt)
   `C@0x53a0–0x5408,0x558c–0x5594`. [RSA wrapper](evidence/execution-20261028/crypto-rsa.dis.txt)
   `C@0x6a80–0x6b28` checks scheme/modulus/signature length and calls
   `mbedtls_rsa_rsassa_pkcs1_v15_verify`. This is a legacy verification path,
   not evidence that all packages use MD5, or that signatures can be bypassed.
3. **Legacy public trust anchor.** Main calls `ZZ0096` at `U@0x4898`;
   [loader](evidence/execution-20261028/crypto-legacy-key.dis.txt)
   `C@0x6b60–0x6b88` resolves a 162-byte DER public key via GOT VA `0x1c0b0`.
   Its R_PPC_RELATIVE addend points to `C@0xb2c4`. Host DER parsing yields
   RSA **1024 bits**, exponent **65537**, DER SHA-256
   `50ff475d72eeadbaef22fe0b83eb7dd1c566cbeed22e648aa9c7c09577949e15`.
   [Anchor metadata](evidence/execution-20261028/legacy-public-anchor.json) and
   [main setup](evidence/execution-20261028/upgrade-key-setup.dis.txt) preserve
   the derivation. This identifies a legacy anchor, not the entire envelope
   trust chain, key rotation policy or installed-device key.
4. **Sonos envelope verification.** [Envelope handler](evidence/execution-20261028/upgrade-envelope-signature.dis.txt)
   `U@0x767c` parses through `ZZ0121`; `U@0x76dc–0x772c` finalizes a 32-byte
   digest and passes callbacks plus hash selector 1 to `ZZ0124`.
   [Envelope entry](evidence/execution-20261028/crypto-envelope-entry.dis.txt)
   `C@0x8b34` calls `ZZ0125`; [verifier](evidence/execution-20261028/crypto-envelope-verifier.dis.txt)
   `C@0x8970–0x898c,0x8a70–0x8a8c` invokes key-selection and verification
   callbacks. The supplied verifier is `ZZ0110`, forwarding to `ZZ0109` at
   `C@0x6b48`. Selector 1 is SHA-256 in the hash/RSA wrappers. The full
   callback-selected trust provenance, envelope nesting and accepted-key set
   remain incomplete; the legacy key must not be substituted for them.
5. **Hash coverage boundary.** [Stream helper](evidence/execution-20261028/upgrade-hash-stream.dis.txt)
   `U@0x5614–0x5664` updates active digest contexts. The [reader](evidence/execution-20261028/upgrade-payload-reader.dis.txt)
   `U@0x607c,0x6110–0x6114` gates hashing on its argument. The legacy handler
   reads signature bytes with a zero hash argument. Full authenticated ranges,
   optional-record handling, compatibility/downgrade gates and all callers have
   not yet been audited end-to-end. No verify-before-every-write claim is made.
6. **Validation before the inspected local install call.** [Local wrapper](evidence/execution-20261028/upgrade-validate-install.dis.txt)
   `U@0x7ca8–0x7ccc` calls the parser and branches on a nonzero result before
   calling the install routine. This is one traced caller; it does not certify
   every coordinator/network path or time-of-check behavior.
7. **Slot/generation and writes.** [Installer](evidence/execution-20261028/upgrade-install.dis.txt)
   `U@0x5888–0x5924` reads bootsection and bootgeneration using fopen/fscanf,
   then reports destination `1 - section` and `generation + 1`. The strings
   are at `U@0x19aac,0x19acc,0x19aec`. It invokes the inline flash routine at
   `U@0x59d0`; [destination builder](evidence/execution-20261028/upgrade-slot-destination.dis.txt)
   `U@0x99f8` computes `1 - section`. This older rootfs lacks the requested
   `lib/libflash.so.1` path (extraction.json); the later Fenway library's offsets
   cannot describe this inline implementation. Complete OOB commit ordering,
   readback coverage, physical layout and power-loss behavior remain open.

The [package installation script](evidence/execution-20261028/package-install-script.txt)
is data only and was never run. Original lines 6–37 can remount JFFS, restore
selected files, save logs, remove files and sync; line 37 creates a conditional
reboot loop. Lines 40–108 can stop services/unmount filesystems and set a volatile
upgrade flag. Its existence is not a RAM-only custom-image boot facility.

Moggie's own updater uses a separate RSA-2048/SHA-256 scheme
(`firmware/updater/manifest.c:360–401`, `rsa.c:131–183`) and a placeholder key
(`pubkey_dev.h:1–13`). Its chooser writes persistent boot metadata
(`firmware/bootchooser/init:192–223,298–339`). Moggie's `bootslot`, `running_slot`,
`boot_ok`, two-attempt rule and custom A/B dimensions are **not stock findings**.
No stock `boot_ok` producer/consumer or health rollback rule is established here.

`0x5779` decompresses to 1,511,544 bytes, SHA-256
`c0a562fa670d1f620c249c8e5857388a575d85fa4fe3f5ce587720719509bf51`.

`bootsection`, `bootgeneration` and SquashFS strings have their own recorded

## CONFIDENCE

- **High, version-bounded:** old init instructions, persistent write sites,
  package boundaries, kernel identities, FDT properties, legacy public-key
  location/parameters and preserved signature call sites. Evidence is static
  and bound to the exact hashes above; no runtime outcome is implied.
- **High, capture-bounded:** ZP5S banner and S0/S1/KP/G/handoff messages exist in
  the extended log. No firmware version, Linux health or rollback policy follows
  from those messages alone.
- **Incomplete:** envelope trust provenance, authenticated byte ranges across
  all callers, watchdog and flash commit ordering. No exhaustive verification
  inventory or current-device trust claim is made.
- **Provisional:** route priorities and expected information value.
